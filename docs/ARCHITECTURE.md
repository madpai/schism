# Godot 4.7.2 / GDScript / Compatibility renderer

> DO NOT TURN SCHISM BACK INTO A MENU-HEAVY DASHBOARD GAME. The player interacts with places and objects.

Godot is selected for Android lifecycle, touch, 2D scenes, lightweight shaders, headless tests and established export support. GDScript avoids experimental mobile C# dependencies. Rendering uses a scene background plus independent interactive object overlays and environmental animation. The GL Compatibility renderer reaches older mobile GPUs. No runtime web service.

mobile/src/simulation.gd: deterministic validated command reducer; independent of Node, rendering, clocks, storage and network. Takes state, command and authored catalog, returns copied next state and events or rejects without mutation. Revision and serial counters scope IDs. Random state is stored. Transaction boundaries include needs/time, items, job stage, money/tax, detection and legal consequences together.

mobile/src/save_store.gd: versioned JSON envelope with payload SHA-256, revision, two rotating verified generations and atomic replacement of the older slot. Flush before replacement. A corrupt or missing newest slot falls back to the highest verified revision. Unsupported future schema opens recovery error rather than resetting or overwriting. v1/v2/v3 migration adds defaults without deleting possessions. Separate app namespace leaves browser citizen databases untouched.

mobile/src/session.gd: local command authority, change signals, persistence boundary, lifecycle hooks. State changes only after successful durable write; failure rolls back visible state and shows an actionable storage notice. mobile/src/main.gd owns navigation, sheets, scenes and object interaction. Authored content in mobile/data/catalog.json, scenes.json and objects.json. `src/presentation.gd` maps authoritative job/inventory state to raster textures and scene variants; it performs no transactions. All hotspot coordinates normalized to the scene canvas.

Item shape: id, kind, label, owner, rightful_owner, serial, origin, condition, acquired_minute, expiry_minute, storage, cold_minutes, legal, metadata, history. Money discoveries retain an evidence instance even after wallet transfer. Stage shape: id, job, stage, garments/crates, inspections, sorted/loaded, detergent/cycle, quality, found objects, risks, worked_minutes. Receipt is a once-settled state transition and immutable bounded event record.

Save schema v6 records identity/appearance, needs, wallet, housing, employment/history, inventory/instances/custody, legal/camp, room upgrades, discoveries, time, events/decisions, settings, random state, command sequence and revision. New fields default during migration. Old browser saves remain supported by the untouched legacy code and are deliberately not reinterpreted as a new-game wallet.

Android uses official export templates, Java 17 and the pinned template’s SDK components (measured minimum API 24, target API 36). Debug APK is for sideload testing, not a signed Play release. Release keystore stays outside version control. See https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_android.html.

Storage keeps legal ownership separate from bag/locker/fridge placement. Relocation is a validated home-only command. Action-time accrues cold_minutes only for unspoiled food physically in a powered fridge, capped at 4320 minutes. Taking food out stops accrual without deleting prior cooling. v3 households retain their former global allowance for existing owned food once during migration; new purchases receive none. No offline cooling/decay tick. Existing schema 3 item serials also recover the serial counter to avoid ID reuse in sparse older records.

Presentation 0.3 keeps schema 4 unchanged. Plain bounded Panels, wrapped buttons and internal ScrollContainers prevent content minimum sizes from expanding interaction sheets beyond the viewport. Backpack paging is ephemeral view state. Washer animation is a masked shader, so pausing, disabling effects or restoring a save cannot repeat a wash, wage or resource charge.

Living City 0.4 adds `identity.background` and `city={encounters,flags,security_favor,supplies}`. Existing citizens migrate to the neutral resident background without receiving new possessions. Five new backgrounds share the same starting money, needs, jobs and opportunities; individual paper mementos and contextual knowledge distinguish them. Migration validates new record types, preserves unknown metadata, and derives per-garment progress from old laundry stages.

`available_encounters(state)` is a pure authority query. Physical encounter objects submit `event_choice`; the reducer recomputes played-day cooldowns, location, employment, inventory custody and prior decisions before committing consequences. The bounded presentation event log is never used as cooldown authority. The service corridor is an ordinary street route; optional inspection never gates essential travel. No rendering or wall-clock timer triggers an encounter transaction.

`cloth_activity.gd` draws retained raster garments and emits commands for drag/tap loading, collection and sequenced folds. Each garment stores loaded/unloaded/folds. Completing each batch stage charges its original minutes once; total laundry remains 240 minutes. Bulk load/collect/fold commands are rejected atomically, including for experienced workers; each garment must be handled. Opening the hatch during collection stops the existing washer motion without restarting a wash.

Object art uses individually authored native-pixel regions rather than assuming generated art obeys a regular grid. The alpha-isolation shader discards alpha <=16/255 without applying texture color twice. `art/validate.py` checks complete silhouette components and eight-pixel visible-alpha gutters, along with hashes and original hotspot preservation. This validation requires Pillow, also used by Android screenshot runners. Original image outputs remain unchanged.

Schema 6 adds the manual civic tax account. Gross wages accrue integer 12% assessments using the existing fractional remainder. `taxes.accrued` holds unbilled assessments; `due` holds billed unpaid debt; `grace_due` is its current one-day grace subset. Billing occurs every 4320 played minutes, with chronological grace expiration after 1440 minutes. `pay_tax` at the bureau retires overdue, grace and accrued amounts in that order. `tax_paid` records actual cash only; labor credits are recorded separately. The bounded ledger is display evidence, never balance authority. Legacy wages are never reassessed or refunded.

An overdue street arrival warns the citizen and preserves a direct route to the bureau. Departing the street elsewhere while flagged, or presenting papers at the service gate, admits the citizen to tax detention without interrupting an active shift. Correction orders create two metal and one fabric supply unit and retire up to one credit of tax. Tax/mixed detention requires cleared debt and three minimum orders; further orders remain available while debt remains. Tax deadlines and housing billing pause during detention. Legacy detainees begin their newly introduced tax pause at the migration minute, avoiding duplicate pause credit. Payment buttons carry an expected revision to reject stale activation.

Paperwork 0.5 uses `paper_document.gd` to draw a retained original clipboard texture in three horizontal regions. Only the parchment center stretches; readable writing and 64-unit controls remain ordinary native UI outside scene effects. Vacancy checkboxes change ephemeral selection only. One guarded signature submits `apply_job` with the captured revision; cancelling or process death discards the draft. Clothes acquire their gesture before ancestor scrolling, freeze its offset, and restore exact filter/deadzone settings on release, cancellation, focus loss or removal. Blank-space gestures remain scrollable. Schema remains 6.
